# Verification tax

Date: 2026-08
Attached to: You can prove it
Optional Coach drill: Before you call the work successful, name the check that would have caught today’s error.

AI models made code generation cheaper while verification still requires careful work.

DORA’s 2026 follow-up on AI return on investment calls the audit work a verification tax: teams spend some of the time saved on writing code by checking the generated result, and that cost appears before the benefit. Stack Overflow reported that trust fell while usage rose. Sonar’s survey of working engineers found that almost nobody fully trusts AI-generated code to work correctly, even though a large share of committed code has already involved a model. As the tools improved, engineers gained more specific reasons to check their output.

The world server shows the same problem on a smaller scale. Its test suite passes even though the health endpoint reports an empty world as unhealthy and the server accepts any position a client reports. The existing tests leave those known risks exposed. A coverage dashboard can therefore report success while important behavior remains unchecked.

Apply the brief in this lesson:

1. Before trusting a check that passes after a fix, run it against the broken state and watch it fail.
2. Treat a model’s claim that the code works as a proposal that still needs verification.
3. Provide a command a stranger can run independently. That command makes the verification work public.

Industry terms may change, but generated work will still need verification. Whenever you work with an assistant, you spend time checking its output whether or not you record that time. This lesson asks you to make the cost visible and keep the evidence.
